# damian-buho/systemlint

A linter for operating systems: a Rust core that collects host facts and judges them with declarative rules, plus one plugin binary per domain.

## Goal

Every line systemlint prints is actionable and every finding is real: zero false positives. A finding that a race, a vanished file, a short-lived process or a missing privilege can cause is a defect in systemlint, not in the host.

## Key facts

- Cargo workspace under `crates/`: `systemlint` (core), `systemlint-protocol` (the only crate a plugin must use), `systemlint-formats`, `systemlint-apt`, `systemlint-sshd`, `systemlint-env`.
- A plugin is `fn op(Request) -> Result<Reply>` in its `lib.rs` behind a two-line `main.rs`; it never does I/O. Protocol and collector schema: `docs/how-to/protocol.md`, `docs/how-to/collectors.md`.
- Plugins are found only in `../lib/systemlint/plugins/` beside the core and in config-named directories, refused when they or any directory above are not owned by root, the user or the running core’s owner, or group/other-writable. A checkout under a 0775 directory is refused by design: install to a 0755 path to try it.
- Version: `SYSTEMLINT_VERSION` stamped at compile time (`systemlint_protocol::VERSION`), else the workspace `Cargo.toml` version.
- Release binaries: `.scripts/build-binaries.sh` builds every crate with a `src/main.rs` as static musl for `TARGET_OS`/`TARGET_ARCH` into `dist/<crate>-linux-<uname -m>`, plus `dist/systemlint-linux-<uname -m>.tar.gz`, the relocatable install tree (`bin/`, `lib/systemlint/plugins/`, `share/systemlint/`, modes normalised, mtime from the commit) that a future nfpm package maps too; every asset matches the release actions’ `dist/systemlint-*` glob. The `build-binaries` tool runs it in `b19/rust:musl`. The host needs `rustup target add x86_64-unknown-linux-musl`; arm64 builds in CI only.
- Collectors: shipped ones in `collectors/*.yaml`, installed to `../share/systemlint/collectors/` beside the core, plus config `collect.directories`; same trust walk as plugins. Every path read goes through `source::Root` (`openat2` `RESOLVE_IN_ROOT`), live mode being root `/`, so never read a subject file with `std::fs`.
- Facts document: facts at the top level beside `meta` and `collectors`; a reply’s `facts` object lands AT `into`, `redact` entries are JSON Pointers into it. `collect()` takes the clock in `Options.now`.
- Try a change end-to-end with `make install-binary`: it unpacks the host archive into `SYSTEMLINT_PREFIX` (default `~/.systemlint`, a 0755 child of the home directory, since `~/.local` is 0775 and the trust walk refuses it) and links `~/.local/bin/systemlint` to its core, which finds the tree through `current_exe().canonicalize()`. It never removes a file the archive no longer ships.
- Rule engine (shipped rulesets in `rulesets/*.yaml`): `rules.rs` (specs, rulesets, selectors), `judge.rs` (ruleset `when` first as `not-applicable`, `manual` rules, subjects, `when`, the outcomes, scores, waivers, `x-version`), `comply.rs`, `report.rs`; format and exit codes in `docs/how-to/rules.md`. Rulesets ship to `../share/systemlint/rulesets/`, catalogs to `../share/systemlint/standards/`, plus `lint.directories` and each one’s `standards` sibling (`comply::directories`; `Library::load` skips a catalog, catalog lookup a ruleset); same trust walk. `lint --standard S` adds `S:*` (`Library::select_for`) and `comply::overall(..).code()` replaces `--fail-on` as the exit code. Waiver expiry is the only judgement given the lint clock (`today`), so tests pass the day in. A subject displays as `Check::subject_label` (its last key, also `{subject}`); `subject_text` (every key joined) stays the identity JSON, SARIF fingerprints and waivers use, and a waiver glob matches either.
- Config: `config::layers` lists system, user (XDG), `./.systemlint.yaml`, `SYSTEMLINT_CONFIG`, `--config`, lowest first, each a `config::Layer` (the project one dropped by `--no-project-config`, skipped by `project-config: false`, which only an `Optional` layer may set); `Config::layered` reads each as a JSON tree, resolves its relative directories beside it, checks it alone (so an error names the file), and deep-merges maps while replacing lists whole. A flag that defaults from config is an `Option` resolved `flag.or(config).unwrap_or(default)`. `tests/cli.rs` runs the core through `core()`, an empty `XDG_CONFIG_HOME` and working directory, so a host’s own config never leaks in. Docs: `docs/how-to/configuration.md`.
- Every YAML read goes through `yaml::from_str` (`strict_booleans`): serde-saphyr’s default turns `no`, `off` and `y` into booleans in an untyped `Value`, so `Enabled: no` or `severity: off` would silently change meaning.
- Image: `b19/rust` builder → `b19/ubuntu`; core in `/usr/local/bin`, plugins in `/usr/local/lib/systemlint/plugins`, collectors and rulesets in `/usr/local/share/systemlint/`.
- License: the projectfile `license.spdx` (AGPL-3.0-only); every file scaffolded from the projectfile takes that license too.
- apt: the `apt` ruleset’s `when` over `os.release` (`ID`, or a word of `ID_LIKE`) limits it to Debian, Ubuntu and their derivatives, so a test document judged by it carries `os.release`. `systemlint-apt` keys a source `path:line` (paragraph or line start); `sources` needs `apt.lists` and matches a source to its cached Release by apt’s list filename (`sources::list_name`). Facts and rules: `docs/how-to/apt.md`. `crates/systemlint/tests/apt.rs` reads fixtures through `collect::inputs` and calls the plugin libraries in-process (dev-dependencies), since the nextest tool builds only the core’s own binaries; `fixtures/apt-misconfigured` fails every `apt` rule once.
- files: one `files-<group>` collector per domain into `files.<group>` (`formats stat`), so one unreadable directory fails its group alone; `judge::walk` binds a failed collector’s `into` key under a `*` as an `unknown` subject. Git keeps no modes, so `tests/files.rs` builds its root under `CARGO_TARGET_TMPDIR` with explicit modes, parents included (the 0775 umask makes `usr` group-writable). Facts and rules: `docs/how-to/files.md`.
- sshd: one `sshd` collector reads the files and runs `sshd -T` (a collector with `files` keeps them under `--root` and drops its `exec`; an absent program reaches the plugin as exit 127); the plugin takes the global config from `-T` when it exits 0, else from the files over `src/defaults/<upstream>.txt` (`sshd -T -f /dev/null` per OpenSSH version, picked from `apt.installed`, which the op `needs`; `.scripts/capture-sshd-defaults.sh IMAGE…` captures one, then list it in `DEFAULTS`), and `Match` blocks always from the files, merged; keywords `Match` refuses (`config::MATCH`, from `servconf.c`) go to `sshd.global.<main>` only, so a block never repeats them. `tests/sshd.rs` pins that files and the captured `fixtures/sshd/sshd-T.txt` give identical outcomes. Facts and rules: `docs/how-to/sshd.md`.
- env: five `env-<source>` collectors into `env.files|defaults|units|processes|image`, one environment per file, unit, service or image (`{kind, vars, path}`); `systemlint-env` marks every value outside `env::CLEAR` and `env::TOGGLES` (switch words) in the reply’s `hash`, and the core replaces it with an HMAC under `Options.hash_key` (random per run, or `collect.hash-key`), so the key never reaches a plugin. `env-processes` is `live: true` and needs root; `env-image` reads `--image-config` (`read.image-config`), a host file outside the root. Rules over a whole `vars` object (`properties: {LD_PRELOAD: false}`), since an absent fact is `unknown`. `fixtures/services` fails every `env` rule once, its fake `/proc` read with `live` set in `tests/env.rs`. Facts and rules: `docs/how-to/env.md`; sysctl, Docker and unit facts: `docs/how-to/services.md`.
- Outputs: `lint --format sarif|textfile` in `report.rs`, `-o/--output` (also on `facts`) through `document::write` (temporary sibling, rename); `docs/how-to/outputs.md`. `action.yaml` runs `.scripts/action/lint.sh`: `facts` once as root with only `DAC_READ_SEARCH`, then `lint -` twice as the runner user; an image subject is `--mount type=image`; `docs/how-to/ci.md`. `test.d/1500-lint-own-root.sh` lints the image’s own b19 root in CI.
- A `files` match that is not a regular file is skipped (`source::Root::read` answers `InvalidInput`), so `/etc/default/*` with a directory or a unit masked to `/dev/null` never fails a collector.
- Errors: an I/O failure the user can fix goes through `explain::io` (a sentence, then the fix for its kind); `main.rs` gives each class its own exit code (2 usage, 5 config/rules, 6 input, 7 output, 70 internal, 130 Ctrl-C, whose handler SIGKILLs the children `runner` tracks in `CHILDREN`; a closed stdout dies on `SIGPIPE`, restored to its default since Rust ignores it), pinned in `tests/cli.rs` against the built binary. `crash::install` saves a panic report under `$XDG_STATE_HOME/systemlint/` and prints one line with a pre-filled issue link that leaves the arguments out. Without `-v`, `trail` keeps the last 50 debug records of each `trail::scoped` collector, plugin, and of `trail::CONFIG`, `DISCOVERY` and `INPUT` (exits 5, 4, 6); its error line, or a batch of refusals, prints them indented beneath (`traced`, `fail`, `refused` in `main.rs`), and a crash report gets them all. A read answering `ESRCH` (a `/proc` process that exited) is absent, like `NotFound` (`collect::gone`).
- Integration tests that need files live in `crates/systemlint/tests/` (`CARGO_TARGET_TMPDIR`); fixture scripts are written once behind a `OnceLock` before any test forks, to a temporary name then renamed, since nextest runs each test as its own process and an in-place rewrite of a script another process execs fails with `ETXTBSY`.
