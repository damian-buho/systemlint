# damian-buho/systemlint

A linter for operating systems: a Rust core that collects host facts and judges them with declarative rules, plus one plugin binary per domain.

## Goal

Every line systemlint prints is actionable and every finding is real: zero false positives. A finding that a race, a vanished file, a short-lived process or a missing privilege can cause is a defect in systemlint, not in the host.

- No fakeouts. A check this run could not make for want of a privilege (`EACCES`, `needs root`) is `not run`, naming what it needs, never `unknown`: `unknown` means the fact should be there and is not.
- Human output is for people, never an infodump: no command lists, timings or internals at default verbosity (`-v` has them), empty lines between blocks, counts one per line. Texts follow `docs/how-to/rule-book.md#words`.
- Silence for what was not asked: an opt-in collector left off (`--image-config`, `--network`) prints no block in human output, only its count.
- A finding judges the risk, never the mere presence: a value normal for its owner (a snap’s generated unit, a container image’s own environment, a root-owned read-only path) is not a finding.

## Key facts

- Cargo workspace under `crates/`: `systemlint` (core), `systemlint-protocol` (the only crate a plugin must use), `systemlint-formats`, `systemlint-apt`, `systemlint-sshd`, `systemlint-env`, `systemlint-systemd`, `systemlint-firewall`, `systemlint-proc`.
- A plugin is `fn op(Request) -> Result<Reply>` in its `lib.rs` behind a two-line `main.rs`; it never does I/O. Protocol and collector schema: `docs/how-to/protocol.md`, `docs/how-to/collectors.md`.
- Plugins are found only in `../lib/systemlint/plugins/` beside the core and in config-named directories, refused when they or any directory above are not owned by root, the user or the running core’s owner, or group/other-writable. A checkout under a 0775 directory is refused by design: install to a 0755 path to try it.
- Version: `SYSTEMLINT_VERSION` stamped at compile time (`systemlint_protocol::VERSION`), else the workspace `Cargo.toml` version.
- Release binaries: `.scripts/build-binaries.sh` builds every crate with a `src/main.rs` as static musl for `TARGET_OS`/`TARGET_ARCH` into `dist/<crate>-linux-<uname -m>`, plus `dist/systemlint-linux-<uname -m>.tar.gz`, the relocatable install tree (`bin/`, `lib/systemlint/plugins/`, `share/systemlint/`, modes normalised, mtime from the commit) that a future nfpm package maps too; every asset matches the release actions’ `dist/systemlint-*` glob. The `build-binaries` tool runs it in `b19/rust:musl`. The host needs `rustup target add x86_64-unknown-linux-musl` and `musl-gcc` (`musl-tools`, for `ring`’s C, which the script passes as `CC_<triple>`, a cross target taking `<arch>-linux-gnu-gcc` instead, since `musl-gcc` emits host objects only; without it `M6E_PREFER_LOCAL=false make build-binaries` builds in the image); arm64 builds in CI only.
- Collectors: shipped ones in `collectors/*.yaml`, installed to `../share/systemlint/collectors/` beside the core, plus config `collect.directories` (same trust walk as plugins) and inline `collect.collectors`, which `Config::check` refuses an `exec`, admitted after them through `collector::admit`; `secret: true` hashes every string of the reply (`collect::strings_at`), as `formats exec` output needs; `partial: true` turns an `EACCES` path into `collectors.<id>.unreadable` (`collect::read_partial`), which `judge::owed` binds under `into` as an `unknown` subject, so only an op keying facts by input path may set it. Every path read goes through `source::Root` (`openat2` `RESOLVE_IN_ROOT`), live mode being root `/`, so never read a subject file with `std::fs`. `read.files-from`/`stat-from` name paths through fact patterns (`collect::named`), ordered after the producer of the literal prefix like `needs`, and fail as unknown when it is absent; `{pattern}/glob` (`collector::template`) globs the suffix below each named path, which stays literal (`Root::glob_under`), as the `ssh-user-*` collectors stat every passwd home’s `.ssh`. A refused read (`source::Failure::Denied`, kept through glob and walk) ends a collector `skipped`, so its rules print as `Not run`; an `image-config`, `network` or `containers` collector the run did not ask for is `skipped` with `opt-in: true`, which `report::shown_skip` leaves to the counts. `read.stat-absent` passes a missing stat path as absent (`exists: false`), as inline collectors always do, so a rule joined to it skips a missing home instead of answering `unknown`. A collector’s `read.order: drop-in` hands its files over as systemd reads a conf directory set (`collect::drop_in`), and `read.prefer: exec` keeps the command alone when it exited 0, else the files alone (`collect::prefer_exec`), as `sysctl` reads `sysctl -a` or its sysctl.d files. `read.exec-from` runs one argv per key of a fact map whose value passes `keep`, `{key}` substituted (`collect::execs`, a key with `,`, `=`, a blank or a control character left out); with `split: true`, its only read, `collect::run` sends each command to the op alone and lands each reply at `into.<key>`, so a family op keys an account’s output by the account. A collector whose needed or named fact comes from a skipped collector is skipped too (`collect::skipped_need`), its rules `Not run`; a program not installed (`source::Failure::Absent`) skips it with `absent: true`, inherited like `opt-in`, which `judge::hosted` turns into `not-applicable`, so a missing sshd is `Nothing to check`, never `Not run`.
- Facts document: facts at the top level beside `meta` and `collectors`; a reply’s `facts` object lands AT `into`, `redact` entries are JSON Pointers into it. `collect()` takes the clock in `Options.now`. A collector’s `ttl` (seconds, none meaning forever) is checked only on a loaded document: `main::lint` reads the clock once and `document::expire` turns each `ok` collector past it into `skipped` with `expired: true` and drops its facts at `into`, so its rules print `Not run`. It runs `Options.jobs` collectors at once (`--jobs`, `collect.jobs`, 1 to `runner::MAX_CHILDREN`, the slots Ctrl-C can kill): facts are read on the calling thread, only `run` goes to a scoped worker, and a running collector blocks its dependents like a pending one.
- Try a change end-to-end with `make install-binary`: it unpacks the host archive into `SYSTEMLINT_PREFIX` (default `~/.systemlint`, a 0755 child of the home directory, since `~/.local` is 0775 and the trust walk refuses it) and links `~/.local/bin/systemlint` to its core, which finds the tree through `current_exe().canonicalize()`. It unpacks into `SYSTEMLINT_PREFIX.new` and swaps it in under a `.lock` flock, so the prefix always equals the archive.
- Rule engine (shipped rulesets in `rulesets/*.yaml`): `rules.rs` (specs, rulesets, selectors), `judge.rs` (ruleset `when` first as `not-applicable`, `manual` rules, subjects, `when`, the outcomes, scores, waivers, `x-version`), `expression.rs` (`x-cel`: cel-rust has no type checker, so load refuses only a long, unparsable or unknown-name expression; `judge` binds `facts` once per rule that mentions one and `bound` per check through a thread-local scope, and the keyword answers valid on an undecided evaluation while noting it, which `judge::decided` turns into `unknown`; JSON integers convert to `int`, never `uint`), `report.rs`; format and exit codes in `docs/how-to/rules.md`. Rulesets ship to `../share/systemlint/rulesets/`, plus `check.directories`; same trust walk. No `--tags` or `check.tags` selects `rules::DEFAULT` (`default`), which every shipped ruleset carries as ruleset `tags` (inherited by the rules it defines), and an implicit run prints the rules left out per defining ruleset (`Selected.left_out`, `Library.owners`) on stderr; a standard is only control tags (`<standard>:<control>`), selected with `--tags 'S:*'`, with no catalog or per-control verdict. Waiver expiry is the only judgement given the lint clock (`today`), so tests pass the day in; a waiver’s `target` glob is settled before `lint` (`judge::waivers_for`, the host spelled `host`). A subject displays as `Check::subject_label` (its last key, also `{subject}`); `subject_text` (every key joined) stays the identity JSON, SARIF fingerprints and waivers use, and a waiver glob matches either. `vars::apply` fills a ruleset’s `${name}` in `Library::load` only, so `Library::new` (as tests call it) sees the raw text. A `{path}` segment (`Segment::From`, `judge::resolve`) keys a `when`, `facts`, `suggest` or `same` path by another fact’s string or number, never the binding `fact`, and `same` (`judge::same`) fails a fact unequal to it, so `home/not-owned` joins passwd accounts to home stats keyed by path; YAML flow maps need such a path quoted.
- Shipped rules follow `docs/how-to/rule-book.md`: one small ruleset per subject (rule ID prefix = ruleset name), guards on what is on disk (a binary, a config file) never on a package manager, the effective value judged as its consumer combines keys, a stock default that exposes the host failing all the same, conflicting standards shipped as one rule each under their own control tag, naming each other in `conflicts` (refused at load unless both sides do; `judge::contradict` turns both selected into outcome `conflict`, one human block, never failing), and an upstream check cited by tag plus reference (`lynis` and `{title: Lynis <ID>, url}`), never by its wording; a new rule gets no test of its own (a maintenance burden): tests pin the mechanics rules need (an op option, a schema keyword, a judgement) at their edge with neutral facts, and `tests/hardening.rs` keeps its existing per-rule tests plus that tag and reference go together.
- Config: `config::layers` lists system, user (XDG), `./.systemlint.yaml`, `SYSTEMLINT_CONFIG`, `--config`, lowest first, each a `config::Layer` (the project one dropped by `--no-project-config`, skipped by `project-config: false`, which only an `Optional` layer may set); `Config::layered` reads each as a JSON tree, resolves its relative directories beside it, checks it alone (so an error names the file), and deep-merges maps while replacing lists whole. A flag that defaults from config is an `Option` resolved `flag.or(config).unwrap_or(default)`. `tests/cli.rs` runs the core through `core()`, an empty `XDG_CONFIG_HOME` and working directory, so a host’s own config never leaks in. Docs: `docs/how-to/configuration.md`.
- Every YAML read goes through `yaml::from_str` (`strict_booleans`): serde-saphyr’s default turns `no`, `off` and `y` into booleans in an untyped `Value`, so `Enabled: no` or `severity: off` would silently change meaning.
- Image: `b19/rust` builder → `b19/ubuntu`; core in `/usr/local/bin`, plugins in `/usr/local/lib/systemlint/plugins`, collectors and rulesets in `/usr/local/share/systemlint/`.
- License: the projectfile `license.spdx` (AGPL-3.0-only); every file scaffolded from the projectfile takes that license too.
- apt: the `apt` ruleset’s `when` over `os.release` (`ID`, or a word of `ID_LIKE`) limits it to Debian, Ubuntu and their derivatives, so a test document judged by it carries `os.release`. `systemlint-apt` reads every deb822 text through `systemlint_formats::deb822` (the `deb822` op’s parser) and keys a source `path:line` (paragraph or line start); `sources` needs `apt.lists` and matches a source to its cached Release by apt’s list filename (`sources::list_name`). Facts and rules: `docs/how-to/apt.md`. `crates/systemlint/tests/apt.rs` reads fixtures through `collect::inputs` and calls the plugin libraries in-process (dev-dependencies), since the nextest tool builds only the core’s own binaries; `fixtures/apt-misconfigured` fails every `apt` rule once. `apt-upgrades` composes `apt-get --simulate dist-upgrade` with the generic `formats match` (`parse.with.pattern`, a regular expression whose `key` capture keys each line, its other named captures the fields), one subject per package. `apt-config` (live only) runs `apt-config dump --format "%f='%v'%n"` naming the judged keys, so no other setting (a proxy password) enters the facts, into `apt.config` through `kv`; its rules match keys with `(?i)` `patternProperties`, as apt compares keys without case, and read booleans as apt’s `StringToBool`, an unset key passing where apt’s default is safe; the `unattended-upgrades` ruleset reads the same map. The text ops read a zero-exit command’s stdout keyed by its program, and a non-zero exit fails them (`formats::ran`), so an empty answer is never a failed command.
- Parsers: one op per format FAMILY, never per file or per program, and facts come out typed and structured. The families: documents (`json`, `yaml`, `toml`, `ini`, `csv`, `deb822`); `kv`, one `key value` per line (`=`, ` = ` or whitespace, shell quotes), or several per line split on `records` with `negate` flags, its `strip` and `swap` spelling keys before `repeat` merges them; `words`, whitespace records (`"…"` and `[…]` one token) keyed by the first word as a directive or by named `columns`, or split on another separator for `:` tables; `options`, getopt lines (auditctl, iptables-save); `rainerscript`, rsyslog’s `$` directives, objects and selectors, no typed options; plus `lines` and `exec`. A command is asked for its JSON first (`findmnt --json`, `systemctl --output=json`). A family op takes a few typed options (separator, columns, key, repeat policy), never a pattern; `match` takes one short pattern, without lookaheads, and needing a longer one, or a lookahead in a rule, means a family is missing. Scalars are typed the way the family reads them: a decimal integer with no leading zero becomes a number, and `yes`/`no` never become booleans. A domain op stays only for privacy (`passwd`, `shadow`, `env`) or for an effective value combined across sources (sshd `Match`, systemd sandbox, apt cross-source judgements), and it consumes a family’s output. File order across drop-in directories (same name overrides, then name order) is a core read policy, not an op. Shaping that is not a format’s syntax is a core step (`steps.rs`): `parse` may be a list of text steps (`section`, `skip`), exactly one op, then tree steps (`nest`, `flatten`, `split`, `unit`, `ranges`, each at an optional `at` path), run in `collect::call` around the request, so a test calling a plugin in-process runs `steps::text` and `steps::tree` itself; a key option deciding which keys are one (`strip`, `swap`, `key-underscores`) stays in its op, since only the op’s `repeat` sees input order.
- files: one `files-<group>` collector per domain into `files.<group>` (`formats stat`), so one unreadable directory fails its group alone; `judge::walk` binds a failed collector’s `into` key under a `*` as an `unknown` subject. Git keeps no modes, so `tests/files.rs` builds its root under `CARGO_TARGET_TMPDIR` with explicit modes, parents included (the 0775 umask makes `usr` group-writable). Facts and rules: `docs/how-to/files.md`. A glob’s `*` never lists a directory a wildcard matched through a symlink (`O_NOFOLLOW`), while a literal symlinked directory before a `*` or `**` is listed where it resolves in the root and named by that path, a pattern with no wildcard naming both the link and that directory (`Root::followed`, so merged `/usr`’s `/bin/*` names `/usr/bin/…`, which the collector’s path set dedupes), and its `**` is its whole last component only (`Root::walk`: no symlinked directory below, no other filesystem, past `WALK_CAP` the collector fails), since a literal after it would resolve through a listed symlink; `read.stat-keep` filters stats by schema before the plugin, so the `setuid` inventory sends 30 stats, not a walk of `/usr`, plus their directories (`read.stat-parents`), which the `setuid` rules judge beside the files. It writes `setuid`, outside `files`, so `files/owner` never judges a setuid file owned by a service user.
- sshd: the `sshd` collector (`privileged`, live only, so under `--root` or unprivileged every sshd rule is `Not run`) runs plain `sshd -T` into `sshd.global.<main>` and, through `read.exec-from` over `accounts.passwd` (root and every `login-shell` account), one `sshd -T -C user={key},host=client.invalid,addr=192.0.2.1` per account into `sshd.accounts.<name>`, keeping the keywords `Match` accepts (`config::MATCH`, from `servconf.c`); `sshd.settings.<keyword>` holds every such keyword’s global value under the main file plus each account that differs (empty when none), which the `ssh` rules bind so a global setting fails once and an account only where its `Match` differs; sshd settles `Include`, defaults and `Match` itself, the files are never parsed, and a failed run fails the op. `tests/sshd.rs` reads real captures in `fixtures/sshd` (`.scripts/capture-sshd-fixture.sh IMAGE ACCOUNT…`). `authorized-key-files` (`authorized.rs`) reads no input, only `sshd` and `accounts.passwd`, covering every passwd account (its own run, else `sshd.global`, else no entry) and expanding `%h`/`%u`/`%U`; `authorized-keys` (`keys.rs`) then needs that map to key each read file back to its accounts, so the core passes no binding. Facts and rules: `docs/how-to/sshd.md`.
- env: six `env-<source>` collectors into `env.files|defaults|units|processes|containers|image`, one environment per file, unit, service, container or image (`{kind, vars, path}`); `systemlint-env` marks every value outside `env::CLEAR` and `env::TOGGLES` (switch words) in the reply’s `hash`, and the core replaces it with an HMAC under `Options.hash_key` (random per run, or `collect.hash-key`), so the key never reaches a plugin. `env-defaults` is `partial`, so a 0600 file is one `unknown` subject; `env-processes` is `live: true` and needs root, and leaves a container scope to `env-containers` (`containers: true`, run only with `--containers`, keyed by Docker’s `config.v2.json` name); `env-image` reads `--image-config` (`read.image-config`), a host file outside the root. Rules over a whole `vars` object (`properties: {LD_PRELOAD: false}`), since an absent fact is `unknown`; `PATH`, `LD_LIBRARY_PATH` and `PYTHONPATH` are also split into `path`, `library-path` and `python-path` (`env::SEARCH_PATHS`), whose env rules fail only an empty or relative entry, while `files-path` and `files-search-path` stat the absolute ones for the `files` rules. `fixtures/services` fails every `env` rule once, its fake `/proc` read with `live` set in `tests/env.rs`. Facts and rules: `docs/how-to/env.md`; sysctl, Docker and unit facts: `docs/how-to/services.md`.
- accounts: `accounts-passwd|shadow` (formats `passwd`, `shadow`; `shadow` with `with.passwd` adds `{password: missing}` for an `x` account with no shadow line and `in-passwd` to every line, false for one no account holds, which the passwd-joined rules guard on so it skips rather than answering `unknown`, and ageing fields are days or `null`) and `accounts-group` (`words` on `:`, the password column dropped) key each entry by name, the first line winning as glibc reads it and later lines’ numbers in `shadowed`; `passwd` with `with.shells` (`passwd_with`) adds `login-shell` as getusershell(3) reads `/etc/shells`; `password` is a word (`shadow`, `empty`, `locked`, `hash`), never the hash. A cross-subject rule uses `unique: true` (`judge::collide`), which fails only subjects that passed. Facts and rules: `docs/how-to/accounts.md`.
- auth: `auth-login-defs|pam|limits|pwquality|securetty` into `auth.*`; `kv` for login.defs (whitespace, last line wins, so `UMASK 022` stays the text `022`), `words` columns for pam.d (`type control module`, the rest `arguments`, `inline-comments` cutting at any `#` as Linux-PAM does, entries per file in order as written, `@include` not followed, so a finding names the file holding the line; the rules compare type and control without case, the `-` prefix allowed, and the module by filename) and `words` columns for limits (entries per file in order, since pam_limits ranks user over group over `*` and a rule judges the lists, its case-insensitive compare as `(?i)`). `auth-pwquality` is `kv` over `pwquality.conf.d/*.conf` then `pwquality.conf`, the order libpwquality reads them, so the main file wins. Rulesets `login-defs`, `pam`, `pwquality` (a module argument overrides the file: a number rule skips it, `dictcheck`/`enforcing` judge it over the whole `auth` map), plus `coredump/no-hard-limit`. sudo: `sudo-grants` (`privileged`, live) splits `sudo --list --other-user={key}` over every passwd account but uid 0 through `match`, one entry per printed grant line, so classic sudo and sudo-rs (Ubuntu 26.04’s `sudo`) settle includes, aliases and groups themselves; the core reads through a pipe, which sudo never wraps, and `.scripts/capture-sudo-fixture.sh` captures the same way. `sudoers-check` runs `visudo --check` (`exec`). `sudo-defaults` reads the same per-account output through a `section: Matching Defaults entries` step and `kv` (`records: ","`, `negate: "!"`, `repeat: last`) into `sudo.defaults.<account>`; sudo-rs prints none, so the `sudo-defaults` ruleset guards on `sudo.version`, which `sudo-version` fills only from classic sudo’s `Sudo version` line, and each rule skips an account with no Defaults (sudo allows it nothing). Docs: `docs/how-to/auth.md`.
- systemd: `systemd-state` (`formats systemd`) takes `enabled` and `masked` from unit-directory entries and `.wants`/`.requires` links, so they hold under `--root`, and `active`/`sub` from `systemctl list-units --all --output=json` (output that is not that JSON leaves every unit without them, never `inactive`), since `systemctl show '*'` lists only active units; a unit on disk the manager has not loaded is `inactive`. A rule on one unit binds it with `systemd.state.*` plus `keys: {const: <unit>}`, so a host without the unit has no check. A unit only the manager knows (another unit’s `Conflicts=` names it) carries `active`/`sub` alone, so “installed” is `{required: [masked], properties: {masked: {const: false}}}`, never `masked` checked without `required`. `systemd-units` (`systemlint-systemd units`, files plus `stat`) keys each unit by name, merged through `formats::unit_files` (shared with `env units`), with its link target (`file`, `alias-of`), `type` and `sandbox` (defaults and `DynamicUser=` implications from `systemd.exec(5)`); `services/unconfined-root` judges only enabled, unmasked, non-`oneshot`, non-snap units whose `file` is outside `/usr/lib`, `/lib` and `/run`; `rescue/no-sulogin` binds `sections.Service.ExecStart`, whose values after the last reset are the effective ones. Docs: `docs/how-to/services.md`.
- Outputs: `check --format sarif|textfile` in `report.rs`, `-o/--output` (also on `facts`) through `document::write` (temporary sibling, rename); `docs/how-to/outputs.md`. `action.yaml` runs `.scripts/action/lint.sh`: `facts` once as root with only `DAC_READ_SEARCH`, then `check -` twice as the runner user; an image subject is `--mount type=image`; `docs/how-to/ci.md`. `test.d/1500-lint-own-root.sh` lints the image’s own b19 root in CI. `test.d/1600-fix-apt-root.sh` runs `fix --root` on a built root (test.d runs as the image user and the image ships no OpenSSH, so it pins `apt-list`, not `authorized-keys`).
- fix: a rule’s `remedy` (`fix.rs`) is a closed set that only takes access away (`chmod` clears bits, `chown` and `chgrp` are 0 only, `disable-line` comments out a `path:line` subject in a `fix::Lines` syntax whose every line grants, only while the line still hashes to its fact’s `line-sha256`, and `fix::Plan.kept` holds back any that would leave an owner, the map above the subject, with no line), since an untrusted `.systemlint.yaml` can define rules; `systemlint fix` lints the live host or `--root DIR` (printing paths under it), plans one change per path (`fix::plan`), and `fix::apply` reopens each through `Root::open_for_change` (no final symlink) and compares before changing, so a re-run is a no-op. Docs: `docs/how-to/rules.md#remedies`.
- mounts: `mounts-active` (`live`, `/proc/self/mounts`) and `mounts-fstab` are `words` columns keyed by mount point, the last line winning, options a list with the later option winning (`toggles`), plus what `user`, `users`, `owner` and `group` imply in fstab (`implies`, mount(8)), so the `mounts/fstab-*` rules ask for the bare `nosuid`, `nodev`, `noexec`; a rule over a `live` collection guards `when: {mounts: {required: [active]}}`, which `judge` answers `skip` under `--root` even though the collection is absent before its first `*`. `mounts-usage` statfs every key of `mounts.active` (`read.statfs-from`, a map naming its keys; `source::Root::statfs` waits at most the collector timeout on a thread, since a dead NFS mount hangs it, and an `EACCES` mount is an `unknown` subject, the collector being `partial`); the `disk` rules guard on `collectors.mounts-usage.status` instead, so a failed collector answers `unknown`, not `skip`. Facts and rules: `docs/how-to/files.md#mounts`.
- network: `network: true` collectors (`read.addr|dns|http`, nothing else, never inline) run only with `--network` or `collect.network: true` and never under `--root`; `net.rs` makes every request in the core, each attempt under `collect.timeout`, `net::retry` trying a `Failure::Retry` 3 times with doubling backoff and jitter, and hands `ProbeInput`s to `formats probes`, which keys them `<kind>.<target>`. A target with no answer keeps `error` so its rules are `unknown`; an untrusted certificate is read through `net::Recorder` (the handshake completes, the verdict is recorded) and nothing is sent; `Proxies` comes from the environment once per run. `tests/net.rs` serves addr, DNS, HTTP, HTTPS (an rcgen CA) and a CONNECT proxy on the loopback. The `tls` ruleset binds `probes.*.http.*`, so a network collector writes `into: probes.<name>`; its ruleset `when: {probes: …}` is `not-applicable` with no such collector, since a ruleset guard over a fact no collector produces is false (`judge::guard` `unproduced`), while a rule’s own `when` keeps it `unknown`. `read.dns-server-from` (`collect::Named.servers`, IP addresses only, so `:3` counts what glibc counts; a path pattern’s `:N` likewise counts absolute paths only) turns `read.dns` into the names asked of each named server, one `nameserver` probe each, `answered` false only when every query met silence, a socket this host can’t open being an error (`Failure::Final` from `net::exchange`); the shipped `resolv-conf` (`words` directives) and `resolv-nameservers` (glibc’s first 3, `nameserver.:3`) collectors feed the `resolv` ruleset. Docs: `docs/how-to/collectors.md#network-probes`.
- kernel modules: five `kernel-modules-*` collectors, no op of their own: `shipped`/`builtin` (`formats match`) from every kernel’s `modules.order`/`modules.builtin` (the file’s spelling, `usb-storage`), `blacklist`/`install` (`words` directives, `key-underscores` for kmod’s spelling `usb_storage`, so a rule guards on one and judges the other) from `modprobe --showconfig`, else (`read.prefer: exec`, `--root`) the `modprobe.d` files in drop-in order, `loaded` (`live`, `words` columns) from `/proc/modules`. `match` drops a repeated key with identical fields silently, so a module in a dozen kernels is one subject, and an absent program ends a commands-only collector `skipped` naming it (`source::Failure::Absent`), else reaches the op as exit 127. The `kernel-modules` ruleset binds `kernel.install`/`blacklist` guarded on `kernel.shipped` (a failed modprobe collector stays `unknown`), the rules CIS alone asks for carrying `'!default'` (a rule’s `!tag` drops an inherited one, `rules::tagged`). Docs: `docs/how-to/services.md#kernel-modules`.
- nftables: `nftables` (`live`, `privileged`) runs `nft --json list ruleset` into `nftables.hooks.<ipv4|ipv6>.<hook>` through `systemlint-firewall nftables`, the effective filter per family and hook (an `inet` chain counts for both): `policy` `drop` when any base chain there has it, `drops` when a rule they reach through `jump`/`goto` holds `drop`/`reject` (iptables-nft’s `xt` targets and verdict maps included). The `nftables` ruleset applies once `nftables.service` is enabled, a schema over the whole `systemd.state` map, so a host without the unit is `not-applicable`, never `unknown`. `.scripts/capture-nftables-fixture.sh` loads each `fixtures/nftables/*.nft` in an unprivileged user network namespace, so fixtures need no root. A failed `nft` (no `CAP_NET_ADMIN`) fails the op, so its rules are `unknown`, not `Not run`. Docs: `docs/how-to/services.md#nftables`.
- proc: `processes-services` (`live`, `privileged`, `/proc/*/cgroup` and `/proc/*/maps`) groups every process by its `system.slice` service (`systemlint_formats::proc::owner`, shared with `env`, containers left out) into `processes.services.<unit>` with `pids` and `replaced`, the executable `(deleted)` mappings under `proc::SYSTEM_DIRS`; `restart/replaced-code` fails only an `active` service, since an `activating` oneshot (apt upgrading its own library) is about to exit. Docs: `docs/how-to/services.md#running-services`.
- ports: `ports-listening` (`live`, unprivileged) reads `/proc/net/{tcp,tcp6,udp,udp6}` through `systemlint-proc sockets` into `ports.<tcp|udp>:<port>` with `addresses` (TCP `LISTEN`, UDP unconnected; the kernel’s native-endian hex words decoded with `to_ne_bytes`, so the plugin must run on the kernel’s host; IPv4-mapped shown as IPv4), the network namespace the core runs in; the `ports` rules bind one port by `keys: {const: "tcp:2375"}` and expect every address under `127.0.0.0/8` or `::1`. Docs: `docs/how-to/services.md#listening-sockets`.
- audit: `audit-rules` (`/etc/audit/rules.d/*.rules`) and `audit-rules-loaded` (`privileged`, `auditctl -l`) are `formats options` (`-a` and `-S` split on `,`) into `audit.rules`/`audit.loaded`, each source’s lines in order as records keyed by flag; a rule says some source holds a line with the flags it needs, `not: {additionalProperties: {not: {contains: {required, properties}}}}`, with no lookahead. The `audit` ruleset (no `default` tag, guarded on `auditd.binary`) shares one `$defs` through a YAML anchor and judges what is recorded, not CIS’s spelling: a `-w` watch or `-F path=`/`dir=` with the access, each syscall per architecture on any line, narrowing filters and keys never asked for. `tests/audit.rs` builds the files from each rule’s own `fix` text, so a fix that stops satisfying its rule, or a rule another’s lines satisfy, fails. The `auditd` ruleset (daemon: unit, `auditd-conf` through `kv`, `auditd-logs` stats) guards a rule on one unit’s `active` with a schema over the whole `systemd.state` map, never a pointer to the key, so `--root` (no `active`) and a missing unit answer `skip`, not `unknown`. Docs: `docs/how-to/services.md#kernel-audit-rules`.
- containers: `--containers` (`collect.containers`, root and live only, else one `Containers not checked` note and `meta.containers`) runs `main::containers` after the host, narrowed by `--container` globs (`collect.container`, a non-empty list implying `--containers`) that `targets::Found::named` matches against key, name or short ID: `targets::discover` groups the host’s `/proc/*/cgroup` by the last container scope in each path (`targets::chain`, nested `docker/<ID>` included, parent from the one before), init the lowest PID whose parent is outside, deduped by mount namespace, named from `config.v2.json` (the parent’s root for a nested one), keyed `parent/name`, with its `Config.Image` and, outside a nested one, the overlay `upperdir` of its `/` (`targets::upper_dir`), which `main::containers` walks (`targets::changed`, `CHANGED_CAP`) into `meta.subject.changed`, so `report::shipped` marks a failing path the container never changed as the image’s (a `path:line` by its path, never a subject of a collector whose outcome carries `live: true`); each is collected with `Options.target` into `targets.<key>`, files through `Root::process` (never `Root::open`, whose `canonicalize` turns `/proc/<pid>/root` into `/`; `/proc/self` and `/proc/net` rewritten to the init’s inner PID) and every `exec` through `runner::run` with `Inside` (pidfd `setns` of the namespaces that differ, a second fork into the PID namespace, the middle process closing its fds so `spawn` returns, capabilities cut to the init’s `CapBnd`, no-new-privs, the init’s AppArmor label requested on exec before `setns`, since a fork keeps it and a task writes only its own `attr`; a seccomp filter is only noted in `meta.subject.seccomp`). A `host: true` collector (kernel, boot, hardware), a `containers` one and a `network` one are skipped there with `host: true`, which `judge::hosted` turns into `not-applicable`. Rulesets about logins guard on `os.init` (`os-init`, `/proc/1/comm`, not `live`, so `--root` reads `{}` and judges) naming a real init, `journald` on its unit and `cron` on `cron.binary`; `tests/hardening.rs` `hosted` lays a booted host under every test document. `lint` judges each target alone; `report::*_targets` lay them out, `lint_human_targets` merging the `report::blocks` of every target by first line and grouping targets by the identical rest (`place` words them), a failure block’s subjects one by one (`report::Item`, the image phrase and build step kept apart from the text so differing images still join), then `target_rows`. Docs: `docs/how-to/collectors.md#containers`.
- A `files` match that is not a regular file is skipped (`source::Root::read` answers `InvalidInput`), so `/etc/default/*` with a directory or a unit masked to `/dev/null` never fails a collector.
- Errors: an I/O failure the user can fix goes through `explain::io` (a sentence, then the fix for its kind); `main.rs` gives each class its own exit code (2 usage, 5 config/rules, 6 input, 7 output, 70 internal, 130 Ctrl-C, whose handler SIGKILLs the children `runner` tracks in `CHILDREN`; a closed stdout dies on `SIGPIPE`, restored to its default since Rust ignores it), pinned in `tests/cli.rs` against the built binary, 70 through a seccomp filter that answers `getrandom` with `EPERM` (std falls back to `/dev/urandom`, the hash key does not). `crash::install` saves a panic report under `$XDG_STATE_HOME/systemlint/` and prints one line with a pre-filled issue link that leaves the arguments out. Without `-v`, `trail` keeps the last 50 debug records of each `trail::scoped` collector, plugin, and of `trail::CONFIG`, `DISCOVERY` and `INPUT` (exits 5, 4, 6); its error line, or a batch of refusals, prints them indented beneath (`traced`, `fail`, `refused` in `main.rs`), and a crash report gets them all. `-v --log-format json` writes each record as one JSON object whose `scope` is `trail::current()` (`trail::json`). A read answering `ESRCH` (a `/proc` process that exited) is absent, like `NotFound` (`collect::gone`).
- Integration tests that need files live in `crates/systemlint/tests/` (`CARGO_TARGET_TMPDIR`); fixture scripts are written once behind a `OnceLock` before any test forks, to a temporary name then renamed, since nextest runs each test as its own process and an in-place rewrite of a script another process execs fails with `ETXTBSY`.
